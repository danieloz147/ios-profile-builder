📚 Payload Reference

🔒 When are supervised payloads useful to an attacker? ▶
Scenario A — Corporate device already supervised
Employees at companies that provision devices via MDM/DEP already have supervised devices. A malicious profile installed via social engineering will activate all supervised payloads — no extra steps.
Scenario B — Physical access
Apple Configurator 2 + USB connection = supervise any device on the spot. Relevant for supply chain attacks, stolen device scenarios, or evil-maid engagements.
Scenario C — DEP Hijacking
During corporate device provisioning (ADE/Zero-Touch), there is a window to register the device against an attacker-controlled MDM server instead of the company's. Device enrolls into attacker infra on first boot — fully supervised from day one.
Scenario D — MDM escalation to supervision
Once an MDM profile is installed, the MDM server can escalate the device to supervised mode. Every supervised payload then becomes available for remote push without re-installing a profile.

▶
57×57 or 114×114 px recommended.
Full Screen removes Safari URL bar — looks native.
🎯 Red-Team Angle
  • FullScreen phishing: No URL bar → victim can't distinguish from a real app
  • Credential harvest: Serve a login mirror (banking, HR portal, SSO)
  • Permission grabber: Page requests camera, mic, GPS on load
  • Persistence: Survives Safari cache clears, lives on Home Screen
💡 + Root CA → HTTPS page with green lock and no warnings
📶Wi-Fi
com.apple.wifi.managed
▶
Preload 802.1X credentials — device authenticates silently with attacker EAP server.
🎯 Red-Team Angle
  • Rogue AP: Push SSID + PSK for attacker-controlled AP — auto-joins silently
  • 802.1X cred harvest: WPA2-Enterprise with attacker RADIUS → captures MSCHAPv2/NTLM
  • Hidden AP: Never appears in Settings Wi-Fi list
  • Auto-join: Zero user interaction — connects the moment in range
💡 + VPN → force all traffic through attacker tunnel after join

🌍DNS Settings
com.apple.dnsSettings.managed
▶
Pushed as com.apple.dnsSettings.managed via custom XML. Requires iOS 14+.
🎯 Red-Team Angle
  • Silent MITM: Redirect name resolution → control what domains resolve where
  • Covert C2: DNS-over-HTTPS to attacker server — blends into normal HTTPS traffic
  • Exfil channel: DNS tunneling over a managed DoH resolver
  • Block security tools: Resolve threat-intel feeds / AV update servers to 0.0.0.0
💡 + VPN (On-Demand) → DNS hijacking + full tunnel = covert persistent access
🔀Global HTTP Proxy
com.apple.proxy.http.globalsupervised
▶
⚠️ Supervised devices only. Requires MDM + Supervision (DEP or Apple Configurator). Unsupervised devices will silently ignore this payload.
🎯 Red-Team Angle
  • Classic MITM: All HTTP(S) routed through Burp/ZAP/mitmproxy on attacker server
  • Passive surveillance: Log browsing without touching DNS or routes
  • PAC file control: Auto-proxy URL → dynamically change routing via PAC updates
  • ⚠️ Requires supervision — useful in MDM context or when targeting supervised corporate devices
💡 + Root CA → attacker proxy with trusted cert = zero-warning HTTPS interception

✉️Mail / Exchange

▶

  • Credential capture: Pre-fill username, leave password blank → iOS prompts user, logs it

🚫Restrictions
com.apple.applicationaccess
▶
Restrictions are serialized as com.apple.applicationaccess plist keys. Supervision may be required for some keys.
🎯 Red-Team Angle
  • Security degradation: Disable VPN toggle → lock victim into attacker-controlled routes
  • Malicious DoS: Disable App Install + Safari + AirDrop = severely degraded device
  • Anti-forensics: Disable screenshot + screen recording → victim can't document
  • Loosen defenses: Allow untrusted app sources to enable sideloading
💡 + MDM → dynamically change restrictions remotely without re-installing profile
📡MDM Enrollment
⚠ Full device control
▶
8191 = full rights
🎯 Red-Team Angle — Maximum Access
  • Remote wipe/lock: Silently wipe or lock the device on command
  • App install/removal: Push or remove any app over-the-air
